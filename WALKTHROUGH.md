# Walkthrough

Every block below is real output from `tools/dte.py` on a toy project, generated by `tools/walkthrough.py`, so it is exact for this version. The project is a small service with a config loader. Owner is `ada`, the agent is `bot`.

## Day one

Scaffold the project.

```
$ dte init
created: dte.cfg, .dteignore, decisions/ (with inbox/)
next:
  1. write the core: dte new A --title "<goal>" --by <owner> --made-by human   (three to six of these)
  2. edit dte.cfg: authority map, docs globs, retire mode
  3. put the agent protocol (CLAUDE.md from the DTE repo) into your agent instructions
  4. dte validate, then dte coverage: that number is the adoption gauge
```

The owner writes the core. Ring A has no parents.

```
$ dte new A --title "Config comes from one source of truth at startup" --by ada --made-by human --decision "All configuration is read once at startup from a single declared source." --why "Runtime config drift caused two outages last year."
created A1 "Config comes from one source of truth at startup" at decisions/A/A1.md
  cite it as dte:A1 from what it governs
```

```
$ dte new A --title "The service stays runnable by one person on a laptop" --by ada --made-by human --decision "Everything needed to run locally is in the repo." --why "Onboarding time is the constraint, not throughput."
created A2 "The service stays runnable by one person on a laptop" at decisions/A/A2.md
  cite it as dte:A2 from what it governs
```

The agent decides at ring B, citing both core goals.

```
$ dte new B --title "Config is a single YAML file, path given by CONFIG_PATH" --by bot --parents A1,A2 --decision "One YAML file. Its path is CONFIG_PATH; default ./config.yml." --why "One file satisfies A1; a checked-in default satisfies A2." --confidence medium
created B1 "Config is a single YAML file, path given by CONFIG_PATH" at decisions/B/B1.md
```


## The owner ratifies

Ratified nodes become human-held: an agent can no longer retire or move them without a human's name.

```
$ dte ratify B1 B2 --by ada
ratified B1 "Config is a single YAML file, path given by CONFIG_PATH" by ada
  it is now human-held (B11)
ratified B2 "Config values are validated against a schema before use" by ada
  it is now human-held (B11)
```

## A subagent is briefed

An orchestrator at ring B spawns a subagent to work under B2 and hands it this block.

```
$ dte brief C --under B2
DTE BRIEF: you operate at ring C of this project's decision tree.

Rules:
  1. Decide only at ring C or deeper. Create decisions with
     `python dte.py new C --title "..." --by <you> --parents <ids> --decision "..." --why "..."`.
  2. Anything that belongs at ring B or shallower, or whose ring is unclear, is not yours:
     write decisions/inbox/<slug>.md and ask orchestrator.
  3. Cite what your work serves: `python dte.py cite <file> <ID>`. Refer to every decision as ID plus its title.
  4. Never change a decision made or ratified by a human. Before you finish, run
     `DTE_RING=C python dte.py validate`; it must print OK.

Decisions above your ring that bind you relevant to B2 (2):
  ring A:
    A1 Config comes from one source of truth at startup [human-held]
  ring B:
    B2 Config values are validated against a schema before use (ai) [human-held]

Your subtree: `python dte.py tree --under B2`; read any node with `python dte.py show <ID>`.
```

## Reverting a decision

The agent tries to revert the human-held B2 and is refused.

```
$ dte retire B2 --by bot
B2 is human-held; retiring it needs --authorized-by <human>  (B11)
```

With the owner's authorization the revert goes through. The report is the blast radius.

```
$ dte retire B2 --by bot --authorized-by ada
retired B2 "Config values are validated against a schema before use"
  reverted; file deleted, ledger line written (text in git history)
  these now fail validation until re-pointed or retired (blast radius of the revert):
    src/validate.py
    C1 The schema lives next to the loader as a Python dict (ai, unratified)
```

Validation now fails until every item in that radius is dealt with. C1 is an orphan; validate.py cites a retired node.


## Integrating

The JSON is the join surface for a structural graph: `citations[].file` is the key.

```
$ dte export --out tree.json
wrote .\tree.json: 4 nodes, 4 citations, 2 retired, 0 inbox
```

That is the whole life cycle: write the core, decide beneath it, cite, validate, ratify, brief, revert, repair, promote, export. Nothing above was typed into a frontmatter block by hand.
