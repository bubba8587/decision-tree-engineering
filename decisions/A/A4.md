## Decision

DTE is a package. It exists to be adopted by other repositories and the agents
working in them: dropped into an existing, live project without a rewrite, and
run alongside structural methods such as graph engineering rather than in place
of them. This repository holds the package and its reference tool. It is not
the product and it is not a standalone project.

## Why

The owner's founding constraints: DTE "works alongside, rather than supersedes,
something like graph engineering", and it is to be built so it can be applied
to the owner's other projects. On 2026-09-05 the owner sharpened the point
while ratifying: the meta work in this repo is meant to finish quickly and stay
finished, after which DTE becomes something other repos and agents add to
themselves. Any format or tool choice that only works here, or only in a
greenfield repo, or that tries to absorb dependency tracking, violates this.
Particular target projects are test beds and are not named in the package.

## Consequences

- Plain-text files and a single-file, dependency-free tool, so DTE can be
  dropped into any stack.
- Incremental coverage rather than all-or-nothing validation.
- DTE models decisions and precedence only. Structural relationships stay in
  the structural tool, and the two cross-reference (see B9).
- There is a finish line: a stable package (tool, SPEC, adoption guide, agent
  protocol) that an agent can install into another repo in one step.
- Nothing in this repo refers to a specific adopting project.
