## Decision

On every `validate`, when the root is a git repository, any path under the
decisions directory that git reports as deleted or renamed is an error,
except paths under `decisions/inbox`, which are meant to disappear when
placed.

## Why

B5 says nodes are never deleted and B23 says they are never renamed, and
until now neither had any enforcement: a leaf with no children and no
citations could vanish and nothing would notice. Git already knows what
was removed. The inbox exemption exists because `dte place` legitimately
removes the inbox file after writing the node.

## Consequences

- Without git the check is absent, and the existing coarse-mode warning
  covers that.
- A move must be done with `dte move`, not `git mv`.
