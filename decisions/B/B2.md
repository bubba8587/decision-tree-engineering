## Decision

An ID is one uppercase letter plus a number (`A1`, `B14`). The letter is the
ring, so precedence is readable from the ID alone. Numbers are never reused.
Moving a node to another ring gives it a new ID in that ring; the old ID goes
in `aliases` and keeps resolving.

## Why

A1 makes position the source of precedence. Encoding the ring in the ID means
anyone reading a citation like `dte:B4` knows without a lookup that it
outranks anything in ring C and is outranked by ring A. That legibility is
worth the cost of re-IDing on a move.

The owner's own sketch used this scheme (A1..A4, B1..B16).

Aliases exist so a move is not a breaking change: citations across a large
project (Solenoid NGC) cannot all be updated atomically, and stale citations
must not silently point nowhere. Tools warn on alias use so cleanup happens.

## Consequences

- `dte next <ring>` allocates numbers; nothing else does.
- The move procedure in SPEC section 7 is mandatory, not optional.
- Single-letter rings cap depth at 26. Treated as a smell, not a limit.

## Alternatives considered

- Opaque stable IDs (`D-0042`) with a `ring:` field: no churn on moves, but
  precedence invisible in citations. Rejected for now; `confidence: medium`
  because at Solenoid NGC scale the churn may argue the other way.
