## Decision

A leaf's frontmatter holds its id, uuid, title, parents, date, who wrote it, and its ratification. `status` appears only when it is not `active`, `made_by` only when it is not `ai`, `conflicts_with` only when it lists something, and the name is the leaf's one alias. Succession is the ledger's fact: under `retire = delete` no leaf carries `supersedes` or `superseded_by`, and `confidence` is gone.

## Why

A field that repeats another record is a second place the same fact can be wrong. The ledger already says what replaced what, ratification already says who settled a leaf, and git already holds every earlier state, so the frontmatter keeps only what nothing else says.

## Consequences

- `dte upgrade` brings a 0.1 tree to this shape, frontmatter only.
- `blast` and `show` derive "formerly superseded" from the ledger.
- How sure an agent was belongs in the Why ("inferred from the code, nobody remembers"), not in a field.
- Under `retire = keep` a retired file still carries `status` and `superseded_by`, because there the file is the record.
