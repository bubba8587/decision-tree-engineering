## Decision

A document that describes the system is either a leaf (a call and its reason) or a spec (what to build). An adopter's existing mechanics docs are its spec layer: declare them in the `specs` globs, one per subsystem. A rationale doc (an out-of-scope list, a list of deferrals) is a set of unlifted leaves.

## Why

A description that is neither has no place in the tree's reach and drifts from the code without anything noticing (A2). Calling what an adopter already has by its layer costs nothing and gives each doc a home.

## Consequences

- Exempt: proposals (they are inbox items), history (git), and reader on-ramps such as a glossary or a mental model.
- Re-homing text that already governs built code owes no contest (B28).
