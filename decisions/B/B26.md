## Decision

Each operation in SPEC section 7 (add, supersede, revert, move, escalate,
place, ratify, declare a contradiction) and each question the paradigm
poses (why does this exist, what does this touch, who decided, what was
retired, where is the decision about X) is a `dte` command. Frontmatter is
written and changed only by the tool. The command set as of this node:
`init`, `new`, `cite`, `show`, `find`, `tree`, `blast`, `trace`,
`conflicts`, `conflict`, `reparent`, `coverage`, `scope`, `next`, `inbox`,
`place`, `move`, `retire`, `retired`, `ratify`, `authority`, `brief`,
`export`, `hook`, `validate`.

## Why

A7 wants agents to run unattended; every hand-written frontmatter block is
a chance to stall on a typo (the agent building this tool misspelled
`superseded_by` twice in one day, caught only by validate). A4 wants
adoption in a live project, where the owner's day-one and every-day
actions, ratifying and searching, must not require opening files. The
owner asked to "flesh out" the commands after seeing the inventory.

`DTE_RING` in the environment is the default for `--as`, so a spawning
agent can hand a subagent its ring without the subagent remembering a
flag (B15 anticipated this).

## Consequences

- `new` writes a complete node from flags, with `TODO` placeholders that
  validate warns about until filled.
- `show` is the chat-friendly view of one decision (A5): lineage,
  children, citing lines, body.
- `ratify` is the owner's one-line action; it flips `proposed` to
  `active` and records the name.
- `export` is the join surface for graph engineering (C12); `init` is
  day one in a new project (C13).
