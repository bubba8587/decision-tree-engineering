## Decision

An agent may keep private memory (Claude Code memory files or equivalent)
and update it freely. Memory is outside the tree and is not scanned. But a
rule about how work in this project is done must also exist as a node; the
memory entry then points to the node rather than being its only home. This
permission is a node so that it can be revoked by editing it.

## Why

Same principle as the CLAUDE.md permission: the owner wants agent
permissions declared as nodes so they can be switched off in one place.
The additional clause comes from A2: when the owner asked what governed
memory, the answer exposed a project rule ("ask in chat, not the dialog")
that lived only in the agent's memory, invisible to the tree and to any
other agent. Mirroring such rules into the tree keeps A2 honest without
making per-agent, per-machine memory a project artifact, which would make
coverage lie.

## Consequences

- The owner's ask-in-chat instruction becomes a human-made node (B20).
- Memory entries that state project rules are rewritten as pointers.
- CLAUDE.md gains: memory is not a substitute for a node.
