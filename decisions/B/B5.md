## Decision

A decision file is never deleted. Superseding or reverting a node changes its
`status` and the file stays. An in-effect node whose parent is superseded or
reverted is an orphan, and orphans are validation errors until re-parented,
superseded, or reverted themselves.

## Why

Tree rings do not disappear when the tree grows; the record of what was
decided and later undone is part of the lineage. Deleting a node would also
delete the only evidence of what its descendants were built on.

Making orphans an error is the enforcement half of A1: reverting a decision
*forces* its blast radius to be walked, because validation fails until every
descendant has been consciously dealt with.

## Consequences

- `dte blast` lists nodes the target supersedes, so a revert can consider
  bringing them back.
- Git history is not a substitute for the file; the node stays in the tree.
