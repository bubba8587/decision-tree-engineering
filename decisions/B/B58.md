## Decision

Every leaf carries a time-ordered uuid (UUIDv7) beside its id. The id stays what people cite; the uuid says which leaf an id means when two branches minted the same number.

## Why

An id collision across branches silently merges two decisions into one file and points each one's citations at the other's text, which breaks the blast radius (A1). A live repo has parallel branches and cloud clones that cannot see every ref (A4), so collisions happen.

## Consequences

- `new`, `place` and `import` write one; `upgrade` backfills one stably from the leaf's date, id and title; `validate` requires one, unique.
- `dte renumber` gives a leaf a fresh id and keeps its uuid; `dte merge-ids <ref>` renumbers every leaf here whose id the ref gives to another.
- `new` warns when the remote has branches this clone has not fetched.
